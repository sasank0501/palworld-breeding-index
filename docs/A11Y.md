# Accessibility — baseline 2026-10-04

The "before" picture for the website plan (Phase 0). Target: **WCAG 2.2 level AA**. Phase 7 re-runs
the same audit and closes this list.

## How to run it

```
npm run dev                                   (one terminal)
APP=http://localhost:5173/ npm run audit-a11y (another)
```

`scripts/audit-a11y.mjs` drives Edge through every screen (Paldex, species, My Pals, pal sheet,
Breeding, Planner) in all four skins, under light and dark system settings — 48 scans — then does a
keyboard pass, a reduced-motion pass and a phone-width pass. Results and screenshots go to
`scripts/.cache/a11y/`. Automated tools find roughly a third of real issues; the manual checks at the
end cover the rest.

## Findings

Each finding: what fails, the WCAG criterion, why it matters, and the fix.

### 1. Text contrast — 1.4.3 Contrast (Minimum)

Normal text needs a contrast ratio of **4.5:1** against its background (3:1 for large text: 24px, or
18.66px bold). Nearly all 2,702 failures come from a handful of shared tokens, so the fix is a few
token changes per skin, not thousands of edits:

| Element | Example (ratio, colours, size) | Cause |
|---|---|---|
| `.sc-dex-count` (×N badge) — 976 | 3.89 · white on `#2f7bff` · 11px | The skin's accent is too light for white text |
| `button.on`, `.sc-btn`, `.sc-gap-depth`, `.sc-roman` | 3.89 · white on `#2f7bff`; Sakurajima 4.3 on `#d6407a` | Same accent |
| `b.go` ("Breed now") — 112 | **2.12** · white on `#ff9a1f` | Orange can never carry white text; use dark text on it |
| `small` / `em` stat colours — 560 | 2.16–3.52 · `#1faa59`, `#59ae85`, `#568bdb` on pale tints | Element/stat colours used as text colour |
| `.sc-pick` — 404 | 2.86–3.97 · `#2f9a62`, `#2b6cd0` on tints | Same |
| `.sc-trait` — 338 | 4.01 · `#6a7390` on `#ecedf1` | The muted-text token is a shade too light |
| `.sc-tag` — 224 | 4.06 · white on `#e0483e` | Red slightly too light for white |
| Sakurajima headings | 4.16 · `#d6407a` on `#fffafb` | Accent used as text colour |

**Fix:** each skin gets two accent tokens — one for **fills** (can stay bright) and a darker
**ink** for text and for text sitting on the fill — and the muted token moves one step darker. Element
colours stay as fills, chips and borders; text on top of them uses ink. Check every pair with the
audit, not by eye.

**Done 2026-10-05: 2,702 → 0** contrast failures over all 48 scans. In `src/design/showcase.css`
each colour that is used as text now has a **text version**: `--accent-strong`, `--good-text`,
`--r-5-text` … `--r-neg-text` (picked per pal by `--rk-text`), `--accent-2-ink`, `--alpha`. The dark
skins (Obsidian, Feybreak) set them to the bright colours, which already pass; the light skins
(Palpagos, Sakurajima) darken each one in HSL lightness just far enough for 4.6:1 (a margin over 4.5),
so the hue stays. Bright colours stay for fills, chips, borders, outlines and bars.

| Token | Palpagos | Sakurajima |
|---|---|---|
| `--accent-strong` (fills under white text, accent-coloured text) | `#2f7bff` → `#045fff` | `#d6407a` → `#ca2b68` |
| `--good-text` | `#1faa59` → `#15723c` | `#2f9a62` → `#226f47` |
| `--r-5-text` / `-4` / `-3` / `-low` / `-neg` | `#845e0b` / `#255eb5` / `#226f47` / `#596078` / `#b12f26` | same, `-4` `#255db2` |
| `--accent-2-ink` ("Breed now" text) | white → `--ink` (6.95:1) | white → `--ink` (7.08:1) |
| `--alpha` (all skins) | `#e0483e` → `#dc3328` | |
| `--ink-soft` | — | `#7a5876` → `#745470` |

Also: `.sc-pick small` lost its `opacity: 0.75` (opacity lowers contrast; it caused Obsidian's
failures), and the audit script now sets the skin through storage and checks it — since the theme
buttons moved into the gear it had been scanning Palpagos four times.

### 2. Very small text — 1.4.4 Resize Text, and readability

Several labels are 8–10px (`font-size: 8px` ×2, `9px` ×3 in the showcase CSS, plus em-sized labels
rendering at 9–10px). WCAG sets no minimum size, but text this small fails low-vision users first and
makes every contrast problem worse. **Fix:** a floor of 12px for any text that carries meaning; 11px
only for decorative numbering.

**Done 2026-10-06:** every 9–11px rule in the showcase CSS and the footer went to 12px; only the
`aria-hidden` rank glyphs stay at 11px. `audit-a11y` now also walks every visible text node and lists
any under the floor (11px for `aria-hidden`): none on all 48 screens. Spotlight dots (3) and work bars
(4, `role="img"`, "level N of 10") done the same day; axe reports 0 violations.

### 3. Spotlight dots are too small to tap — 2.5.8 Target Size (Minimum)

The spotlight picker's dots are 11×11px with 12px of clear space; the minimum is **24×24px** (or
enough space around it). **Fix:** keep the dot drawing small but give each button a 24px hit area
(padding, or a transparent `::before`).

### 4. `aria-label` on a plain `<i>` — 4.1.2 Name, Role, Value

The work-suitability level bars (`Dossier.tsx:170`, `PalSheet.tsx:178`) are
`<i aria-label="1 of 10">`. A label on an element with no role is not read by most screen readers, so
the level is silently lost. **Fix:** `role="img"` on the `<i>` (it is a picture of a number, the way
`Ring` in `parts.tsx` already does it), or a visually hidden span: `<span class="sr-only">level 1 of 10</span>`.

### 5. No `<main>` landmark, no skip link — 1.3.1 Info and Relationships, 2.4.1 Bypass Blocks

Screen-reader users jump between landmarks (`nav`, `main`). There is a `nav` but no `main`, so 480
elements sit outside any landmark, and there is no "Skip to content" link.

**Keyboard cost today: 34 Tab presses to reach the first Paldex tile** (4 tabs, 4 skins, the
spotlight model, its button, 8 spotlight dots, search, 4 view filters, 10 element filters).

**Fix:** wrap the section content in `<main>`; add a skip link as the first focusable element; make the
spotlight dots one Tab stop with arrow keys between them (a "roving tabindex"), which alone saves 7
presses.

**Done 2026-10-05 (part):** `<main id="main">` and a "Skip to content" link (first Tab stop; it
focuses `main` in code, because the URL hash belongs to the app). The `region` rule went 480 → 0.
**Done 2026-10-06:** the spotlight dots are one Tab stop; arrows, Home and End pick a pal and move
focus. The spotlight also pauses while focus is inside it, as it already did on hover (2.2.2).

### 6. Skins ignore the light/dark setting (decision, not a WCAG failure)

All 48 scans gave the same numbers in light and dark: the showcase skins have a single palette each,
and the old `prefers-color-scheme` theme in `src/styles.css` no longer reaches them. WCAG doesn't
require a dark mode, but people who set one often do so for light sensitivity. **Options:** a dark
variant per skin, one dark skin (Mount Obsidian is closest), or leave it as a known gap. Your call.

### 7. Focus is lost when opening and closing a page — 2.4.3 Focus Order

Opening a species with Enter leaves focus on `<body>`; Esc back to the list also leaves it on
`<body>`. A keyboard user has to Tab from the top again (34 presses) to get back to where they were,
and a screen reader announces nothing when the page changes.

**Fix:** on open, move focus to the new page's heading (`tabIndex={-1}` on the `h1`, then `.focus()`);
on Back, focus the tile that opened it. Scroll is already restored, so this is the missing half.

**Done 2026-10-05:** `Showcase.tsx` focuses the new page's `h1` on open (and the Paldex `h1`
straight after an import), and on Back returns focus to whatever opened the page. The audit's
keyboard pass now reports `h1 "Lamball"` after open and the Lamball tile after Back (was `body`
both times). Found with NVDA first: with focus on nothing, it read all 289 tiles aloud.

### 8. The spotlight model is a Tab stop with no visible focus or name

`<model-viewer>` takes focus (for its keyboard camera controls) but shows no focus ring and has an
empty accessible name. **Fix:** an `alt` ("Knocklem, 3D model, rotating") and a visible focus style.

**Done 2026-10-06:** the name was already there (`alt="3D model of Knocklem, chibi style"`, read from
the shadow DOM, which the audit had missed). Focus goes to a div inside model-viewer's shadow root
whose ring is a 1px browser default, and the host never matches `:focus-visible`; `PalModel.tsx`
sets `data-kbd-focus` on the host while that div has keyboard focus, and `styles.css` draws a 3px
accent ring from it.

### 9. Motion that ignores reduced-motion — 2.3.3 Animation from Interactions (AAA, but cheap)

Most animation is already behind `prefers-reduced-motion: no-preference`. Two leaks:
- the legendary gem glint, `src/design/showcase.css:806`, sits outside the media query;
- the spotlight's `<model-viewer>` keeps `auto-rotate` and `autoplay`.

**Fix:** move the gem rule inside the query; drop `auto-rotate`/`autoplay` when
`matchMedia('(prefers-reduced-motion: reduce)')` matches, and add a pause button for anyone who
wants it either way (2.2.2 Pause, Stop, Hide applies to motion longer than 5 seconds).

**Done 2026-10-06:** the gem glint is inside the `no-preference` query. `PalModel.tsx` starts
held still (no auto-rotate, animation paused on its first frame, so the pal is posed, not in its
T-pose) when reduced motion is set, and every stage has a 32px pause/play button in its top-left
corner (`aria-pressed`, label "Pause motion") for everyone; picking an animation clip plays it.
Checked in Edge with reduced motion on and off: held at t=0.05 s and no rotation, then moving
after one click; the audit's reduced-motion pass reports no running animations. Known gap: with
motion allowed, the legendary gem glint (a 2.4 s shimmer on a few tiles) has no pause of its own.

### 10. Phone: the first tile is 1,498px down — UX brief, not WCAG

At 390px there's no horizontal scrolling (good), but the spotlight and filters push the first species
tile almost two screens down. Same issue the UX brief raised; same fix (collapse filters, shorter
spotlight on narrow screens).

## NVDA, first pass (2026-10-05, Firefox, Paldex and Planner)

NVDA also reads whatever the mouse passes over, so a Speech Viewer log mixes page order with mouse
noise; the findings below are the ones that hold up. Fixed the same day:

- **Rank glyphs were read aloud** (◆, ●●●, ✕). Now `aria-hidden`, with words in their place where no
  heading already gives the rank: "rank IV: Lightfooted", "flaw: Brittle" (`TraitGlyph` in
  `shared.tsx`).
- **Placeholder initials** ("An Anubis", "Fu", "Cr") from the art fallback were read before names.
  Now hidden.
- **Bare numbers** in the passive picker ("Eternal Engine 129"): now "129 owned".
- **Search fields named only by their placeholder**, which in the Planner changes to "Anubis, or
  another…" after a pick. Every search now has an `aria-label`, and the Planner announces "8 matches"
  as you type.
- **"1Target species"**: the step number ran into the heading. Hidden from screen readers.
- Paldex tiles now include the count: "Lamball, discovered, 8 owned".

Feybreak, found by eye the same day: its glass `--panel` is 62% opaque, so the settings menu, the
Saved plans menu, the restore dialog and the sort dropdown let the page show through. They use a
solid `--panel-solid` now (`#0a232c`, the glass as it looks over the night sky).

## Phase 7 automated pass (2026-10-09, Edge, dev server and public build)

Scripts in `scripts/.cache/a11y/` (`p7-checks.mjs`, `p7-reflow-hc.mjs`, `p7-planner-kbd.mjs`) and
`scripts/.cache/extract/` (`axe-notice.mjs`, `notice-kbd.mjs`). What they found and what changed:

- **Item 6, dark mode (decided: follow the system).** With no theme picked, Palpagos when the system
  is light, Mount Obsidian when dark, switching live; a pick wins (`skins.ts`). Checked: dark → obsidian,
  light → pal, flips both ways, stored Sakurajima stays.
- **Item 10, phones (decided: fold the filters).** Under 640 px the view switch and element chips sit
  behind a "Filters" button (`aria-expanded`, names the active filters when closed: "Filters Fire"),
  and search shares its row. First tile at 390 px: 1,695 → 1,421 px. The spotlight (808 px tall) is
  the rest of it, and stays as it is by decision.
- **Zoom 200% and reflow 400% (1.4.4, 1.4.10).** All six screens fit at 640 and 320 px wide. Found:
  at 320 × 256 the sticky nav and the floating site notice covered the whole window, so nothing could
  be clicked; under 500 px tall both scroll with the page now.
- **High Contrast (forced colors, emulated).** Found: focus rings drawn as `box-shadow` vanished on
  the search box and the Paldex tiles, and a pressed element chip looked unpressed. A forced-colors
  block in `styles.css` gives a `Highlight` outline and a `Highlight` fill for pressed/selected
  controls. Emulation is not the real thing: still to try in Windows' own contrast themes.
- **Keyboard only, Planner.** Paldex → Planner → Anubis → a preset → Find the lineage → the tree:
  38 key presses, focus visible at every stop. Found: the button was `disabled` while solving, which
  dropped focus onto `<body>`; now `aria-disabled`, with a status message when the lineage is found.
- **Keyboard only, the extraction notice.** Each stage swaps the controls, so the pressed button
  vanished; lost focus now goes to the notice's heading. axe: 4 states × 4 themes clean.
- **Colour alone (1.4.1).** Paldex tile states have words ("IV 221", "Breed now", "3 steps", "Wild
  only") and undiscovered pals are silhouettes; passive ranks have glyphs and words; elements have
  icons and names. The rarity gem differed only in colour: now 1 (common) to 5 (legendary) gems
  (decided 2026-10-09), each with an ink edge for 3:1 (gold on Palpagos was 1.7:1), and tiles say
  the tier in their name ("Jetragon, legendary, not discovered").

## For you: the NVDA pass through the new flows

NVDA + Firefox, keyboard only, mouse still (NVDA also reads what the pointer passes over). On the
public build (`npm run build`, `npx vite preview`), fresh private window:

1. "Try the demo save". The "Add the game art" notice: Tab through it. Is each part named? Is the
   Steam path read sensibly, and is "Copy" clear?
2. Choose `Pal-Windows.pak`. Do you hear the steps ("Starting the reader…", "Opening the game
   file…"), then progress every 10%, not every pal? Does focus stay somewhere sensible?
3. Stop. Do you hear "Finish adding the game art", and where does Tab go next?
4. Settings (the gear) → Game art: are "Add the art from your game…" and the folder option clear?
5. Then the earlier list: species → Back → My Pals → a pal → next/previous.
