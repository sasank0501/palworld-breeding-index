# Accessibility — baseline 2026-10-04

The "before" picture for the website plan (Phase 0). Target: **WCAG 2.2 level AA**. Phase 7 re-runs
the same audit and closes this list.

## How to run it

```
npm run dev                                   (one terminal)
APP=http://localhost:5173/ npm run audit-a11y (another)
```

`scripts/audit-a11y.mjs` drives Edge through every screen (Paldex, species, My Pals, pal sheet,
Breeding, Planner) in all four skins, under light and dark system settings — 48 scans — then does a
keyboard pass, a reduced-motion pass and a phone-width pass. Results and screenshots go to
`scripts/.cache/a11y/`. Automated tools find roughly a third of real issues; the manual checks at the
end cover the rest.

## Findings

Each finding: what fails, the WCAG criterion, why it matters, and the fix.

### 1. Text contrast — 1.4.3 Contrast (Minimum)

Normal text needs a contrast ratio of **4.5:1** against its background (3:1 for large text: 24px, or
18.66px bold). Nearly all 2,702 failures come from a handful of shared tokens, so the fix is a few
token changes per skin, not thousands of edits:

| Element | Example (ratio, colours, size) | Cause |
|---|---|---|
| `.sc-dex-count` (×N badge) — 976 | 3.89 · white on `#2f7bff` · 11px | The skin's accent is too light for white text |
| `button.on`, `.sc-btn`, `.sc-gap-depth`, `.sc-roman` | 3.89 · white on `#2f7bff`; Sakurajima 4.3 on `#d6407a` | Same accent |
| `b.go` ("Breed now") — 112 | **2.12** · white on `#ff9a1f` | Orange can never carry white text; use dark text on it |
| `small` / `em` stat colours — 560 | 2.16–3.52 · `#1faa59`, `#59ae85`, `#568bdb` on pale tints | Element/stat colours used as text colour |
| `.sc-pick` — 404 | 2.86–3.97 · `#2f9a62`, `#2b6cd0` on tints | Same |
| `.sc-trait` — 338 | 4.01 · `#6a7390` on `#ecedf1` | The muted-text token is a shade too light |
| `.sc-tag` — 224 | 4.06 · white on `#e0483e` | Red slightly too light for white |
| Sakurajima headings | 4.16 · `#d6407a` on `#fffafb` | Accent used as text colour |

**Fix:** each skin gets two accent tokens — one for **fills** (can stay bright) and a darker
**ink** for text and for text sitting on the fill — and the muted token moves one step darker. Element
colours stay as fills, chips and borders; text on top of them uses ink. Check every pair with the
audit, not by eye.

### 2. Very small text — 1.4.4 Resize Text, and readability

Several labels are 8–10px (`font-size: 8px` ×2, `9px` ×3 in the showcase CSS, plus em-sized labels
rendering at 9–10px). WCAG sets no minimum size, but text this small fails low-vision users first and
makes every contrast problem worse. **Fix:** a floor of 12px for any text that carries meaning; 11px
only for decorative numbering.

### 3. Spotlight dots are too small to tap — 2.5.8 Target Size (Minimum)

The spotlight picker's dots are 11×11px with 12px of clear space; the minimum is **24×24px** (or
enough space around it). **Fix:** keep the dot drawing small but give each button a 24px hit area
(padding, or a transparent `::before`).

### 4. `aria-label` on a plain `<i>` — 4.1.2 Name, Role, Value

The work-suitability level bars (`Dossier.tsx:170`, `PalSheet.tsx:178`) are
`<i aria-label="1 of 10">`. A label on an element with no role is not read by most screen readers, so
the level is silently lost. **Fix:** `role="img"` on the `<i>` (it is a picture of a number, the way
`Ring` in `parts.tsx` already does it), or a visually hidden span: `<span class="sr-only">level 1 of 10</span>`.

### 5. No `<main>` landmark, no skip link — 1.3.1 Info and Relationships, 2.4.1 Bypass Blocks

Screen-reader users jump between landmarks (`nav`, `main`). There is a `nav` but no `main`, so 480
elements sit outside any landmark, and there is no "Skip to content" link.

**Keyboard cost today: 34 Tab presses to reach the first Paldex tile** (4 tabs, 4 skins, the
spotlight model, its button, 8 spotlight dots, search, 4 view filters, 10 element filters).

**Fix:** wrap the section content in `<main>`; add a skip link as the first focusable element; make the
spotlight dots one Tab stop with arrow keys between them (a "roving tabindex"), which alone saves 7
presses.

### 6. Skins ignore the light/dark setting (decision, not a WCAG failure)

All 48 scans gave the same numbers in light and dark: the showcase skins have a single palette each,
and the old `prefers-color-scheme` theme in `src/styles.css` no longer reaches them. WCAG doesn't
require a dark mode, but people who set one often do so for light sensitivity. **Options:** a dark
variant per skin, one dark skin (Mount Obsidian is closest), or leave it as a known gap. Your call.

### 7. Focus is lost when opening and closing a page — 2.4.3 Focus Order

Opening a species with Enter leaves focus on `<body>`; Esc back to the list also leaves it on
`<body>`. A keyboard user has to Tab from the top again (34 presses) to get back to where they were,
and a screen reader announces nothing when the page changes.

**Fix:** on open, move focus to the new page's heading (`tabIndex={-1}` on the `h1`, then `.focus()`);
on Back, focus the tile that opened it. Scroll is already restored, so this is the missing half.

### 8. The spotlight model is a Tab stop with no visible focus or name

`<model-viewer>` takes focus (for its keyboard camera controls) but shows no focus ring and has an
empty accessible name. **Fix:** an `alt` ("Knocklem, 3D model, rotating") and a visible focus style.

### 9. Motion that ignores reduced-motion — 2.3.3 Animation from Interactions (AAA, but cheap)

Most animation is already behind `prefers-reduced-motion: no-preference`. Two leaks:
- the legendary gem glint, `src/design/showcase.css:806`, sits outside the media query;
- the spotlight's `<model-viewer>` keeps `auto-rotate` and `autoplay`.

**Fix:** move the gem rule inside the query; drop `auto-rotate`/`autoplay` when
`matchMedia('(prefers-reduced-motion: reduce)')` matches, and add a pause button for anyone who
wants it either way (2.2.2 Pause, Stop, Hide applies to motion longer than 5 seconds).

### 10. Phone: the first tile is 1,498px down — UX brief, not WCAG

At 390px there's no horizontal scrolling (good), but the spotlight and filters push the first species
tile almost two screens down. Same issue the UX brief raised; same fix (collapse filters, shorter
spotlight on narrow screens).

## Manual checks still to do

The audit can't do these; they need a person.

- [ ] **NVDA** (free, nvaccess.org): Paldex → open a species → Back → My Pals → open a pal → step
      next/previous. Is every control named? Is the page change announced?
- [ ] **Keyboard only**, mouse unplugged, through the Planner: pick a species, add passives, read
      the tree.
- [ ] **Zoom to 200%** (Ctrl +): does anything overlap or get cut off? (1.4.4, 1.4.10 Reflow)
- [ ] **Windows High Contrast** (Settings → Accessibility → Contrast themes): are buttons and focus
      still visible?
- [ ] **Colour alone** (1.4.1): does anything rely only on colour — rank plates, element tints,
      "breedable now" glow? Each needs a text or shape cue too.
